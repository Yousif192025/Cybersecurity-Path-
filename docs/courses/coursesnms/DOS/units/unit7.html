أساسيات أوامر Windows CMD للأمن السيبراني

الوحدة السابعة: سجلات Windows والتحليل الأمني

Windows Event Logs & Security Analysis

مقدمة الوحدة

في الوحدة السابقة تعرّفت على العمليات والخدمات. في هذه الوحدة ننتقل إلى الذاكرة التاريخية للنظام: سجلات أحداث Windows (Windows Event Logs).

هذه السجلات تسجّل ما يحدث على النظام: تسجيل الدخول، إعادة التشغيل، تثبيت البرامج، تغيير الخدمات، والأخطاء. المحلل الأمني يستخدمها لإعادة بناء ما حدث وربط الأحداث زمنيًا.

سنتعلّم قراءة هذه السجلات باستخدام wevtutil داخل محاكي تعليمي آمن، مع بيانات افتراضية ثابتة. لن تفتح سجلات جهازك، ولن تنفذ أوامر حقيقية.

💡
جميع الأحداث والمستخدمين والأوقات في هذه الوحدة افتراضية بالكامل لأغراض التدريب.

أهداف التعلم

بنهاية هذه الوحدة ستكون قادرًا على:

  1. فهم أهمية سجلات Windows في التحليل الأمني.
  2. التمييز بين سجلات System وApplication وSecurity.
  3. فهم مستويات الأحداث: Information, Warning, Error, Critical, Audit Success, Audit Failure.
  4. قراءة مكونات الحدث: Event ID، Source، Level، Date/Time، User، Description.
  5. استخدام أوامر wevtutil الأساسية لفهم السجلات.
  6. تفسير أرقام أحداث شائعة مثل 4624 و4625 و1102 و6005 في سياقها.
  7. ربط الأحداث زمنيًا (Timeline Analysis) لفهم تسلسل الحوادث.
  8. التعرف على مؤشرات تستحق التحقيق دون افتراض سوء النية تلقائيًا.

المفاهيم الأساسية

قبل الدخول إلى الأوامر، دعنا نثبّت المفاهيم التالية:

Windows Event Logs
سجلات أحداث Windows
خدمة نظام تسجّل الأحداث التي تطرأ على النظام والتطبيقات والأمان، وتُستخدم للتحليل الأمني واستكشاف الأخطاء.
Event Viewer
عارض الأحداث
أداة رسومية لتصفح سجلات Windows. أوامر wevtutil تقدم وظائف مشابهة من سطر الأوامر.
System Log
سجل النظام
أحداث نظام التشغيل: بدء الخدمات، إعادة التشغيل، أخطاء العتاد، تغيير الساعة.
Application Log
سجل التطبيقات
أحداث التطبيقات: أخطاء برامج، تعطل تطبيقات، تحديثات تطبيقات.
Security Log
سجل الأمان
أحداث الأمن: تسجيل الدخول، تغيير الحسابات، تغيير السياسات. يُدار بواسطة سياسات التدقيق.
Event ID
معرّف الحدث
رقم يميّز نوع الحدث. مثل 4624 (تسجيل دخول ناجح) و4625 (فشل تسجيل دخول) و1102 (مسح سجل أمني).
Source / Provider
المصدر
المكوّن أو الخدمة التي سجّلت الحدث، مثل Microsoft-Windows-Security-Auditing أو Service Control Manager.
Level
مستوى الحدث
درجة أهمية الحدث: Information, Warning, Error, Critical, Audit Success, Audit Failure.
Timeline Analysis
التحليل الزمني
ربط الأحداث وفق تسلسلها الزمني لفهم ما حدث قبل الحادث وبعده.
Audit Success / Failure
تدقيق نجاح / فشل
مستويان في سجل الأمان: Success لنجاح عملية مُدقّقة، Failure لفشلها (مثل محاولة تسجيل دخول فاشلة).
⚠️
مهم: سجلات Windows أداة مساعدة للتحليل، لكنها ليست دليلًا قاطعًا منفردًا. الحدث يجب أن يُفسَّر في سياقه، مع مقارنة بالمعلومات الموثوقة.

شرح الأوامر

أوامر هذه الوحدة تدور حول قراءة سجلات Windows دون تعديلها. سنتعلم كل أمر مع مثال افتراضي.

أولًا: wevtutil — الأداة الأساسية

أداة سطر أوامر لقراءة وإدارة سجلات Windows. تُستخدم للاستعلام والقراءة في هذا التدريب، دون تعديل. علاقتها بـ Event Viewer أنها تقدم وظائف مماثلة من سطر الأوامر.

wevtutil /? 
C:\> wevtutil /?

Usage: wevtutil [command] [options]

Commands:
  el      - Enumerate event logs
  gli     - Get log information
  qe      - Query events
  ...
ℹ️
الصيغة الكاملة موثقة في مراجع Microsoft. هنا نعرض فقط ما نستخدمه.

سيناريوهات التحليل الأمني

فيما يلي سيناريوهات افتراضية لتحليل مجموعة أحداث وربطها زمنيًا.

1محاولات تسجيل دخول فاشلة متكررة

سجل الأمان يعرض 3 أحداث 4625 متتالية للحساب CYBERPATH\analyst1 خلال دقيقتين (12:31، 12:32، 12:33).

سؤال: متى تستحق هذه الأحداث التحقيق؟

اعرض التحليل المتوقع
التكرار السريع لمحاولات فاشلة مؤشر يستحق التحقيق: قد يكون خطأ إدخال كلمة مرور، أو محاولة تخمين. الأهم هو ربطها بما بعدها: هل تبعها تسجيل دخول ناجح من مصدر غير معتاد؟ هل تكررت على حسابات متعددة؟ لا يمكن الحكم من الأحداث وحدها.
2تسجيل دخول ناجح بعد سلسلة فاشلة

في 12:31–12:33 ثلاث محاولات فاشلة للحساب analyst1، ثم في 12:35 حدث 4624 ناجح لنفس الحساب.

سؤال: كيف تحلل التسلسل؟

اعرض التحليل المتوقع
التسلسل يستحق التحقيق: نجاح بعد فشل متكرر قد يعني أن كلمة المرور خُمّنت بنجاح. لكن قد يكون المستخدم أدخل كلمة المرور الصحيحة بعد خطأ. الفرق يُحسم بمعرفة: عنوان المصدر، نوع تسجيل الدخول، الوقت، وسياق المستخدم. لا تحكم من الحدث منفردًا.
3حدث إعادة تشغيل النظام

سجل System يعرض 6005 (بدء خدمة سجل الأحداث) في 12:20، و6006 (توقفها) في 12:00.

سؤال: ماذا يعني ذلك؟

اعرض التحليل المتوقع
الفرق بين 6006 (توقف خدمة السجل) و6005 (بدءها) يشير إلى إعادة تشغيل النظام بين 12:00 و12:20. هذا حدث طبيعي، لكن في التحليل الأمني قد يكون مؤشرًا على: تثبيت تحديثات، تغيير إعدادات، أو إجراء من مهاجم. يجب ربطه بأحداث أخرى في نفس النافذة الزمنية.
4حدث مسح سجل أمني (1102)

سجل الأمان يعرض 1102 في 13:00 من الحساب CYBERPATH\admin1.

سؤال: ما دلالة ذلك؟

اعرض التحليل المتوقع
1102 يعني أن سجل الأمان قد مُسح. هذا حدث يستحق التحقيق دائمًا، لأنه قد يخفي آثارًا. لكنه لا يثبت سوء النية تلقائيًا: قد يكون إجراءً إداريًا مشروعًا (مثل صيانة معتمدة). المفتاح هو التحقق من: هل كان مصرحًا به؟ من قام به؟ وماذا حدث قبله وبعده؟
5مقارنة بين أحداث طبيعية وأخرى غير معتادة

طبيعي: 4624 واحد صباحًا من الحساب المعتاد، يتبعه نشاط اعتيادي.
غير معتاد: 4624 في ساعة متأخرة من حساب غير مستخدم عادةً، يتبعه 1102 بعد دقائق.

سؤال: كيف تفرّق بينهما؟

اعرض التحليل المتوقع
الفرق ليس في الحدث نفسه، بل في السياق: التوقيت، الحساب، تكرار الحدث، ما يليه، والمقارنة بالسلوك المعتاد. 4624 وحده ليس مؤشرًا؛ لكن اجتماعه مع توقيت غير معتاد وحساب غير معتاد و1102 لاحق يرفع درجة الاشتباه.

التمارين والتحديات

استخدم المحاكي أعلاه. جميع النتائج افتراضية.

1عرض أسماء السجلات

ما الأمر الذي يعرض قائمة بأسماء السجلات المتاحة؟

اعرض الإجابة
wevtutil el — يعرض السجلات مثل System, Security, Application.
2معلومات سجل System

كيف تعرض معلومات سجل System (الحجم، عدد السجلات، التفعيل)؟

اعرض الإجابة
wevtutil gli System — يعرض الحقول: fileSize، numberOfLogRecords، enabled، إلخ.
3آخر خمسة أحداث في System

ما الأمر الذي يعرض آخر 5 أحداث في سجل System؟

اعرض الإجابة
wevtutil qe System /c:5 /rd:true /f:text — /c:5 للعدد، /rd:true للأحدث أولًا، /f:text للصيغة النصية.
4البحث عن EventID=4625

كيف تبحث عن أحداث فشل تسجيل الدخول؟

اعرض الإجابة
wevtutil qe Security /q:"*[System[(EventID=4625)]]" /f:text
5تحليل تسلسل زمني

اعرض أحداث الأمان الأخيرة. هل ترى تسلسلًا يستحق التحقيق؟

اعرض التحليل
نعم: ثلاث محاولات 4625 فاشلة تتبعها 4624 ناجحة لنفس الحساب. التسلسل يستحق التحقيق، لكن الحكم النهائي يحتاج معلومات إضافية (المصدر، نوع تسجيل الدخول، سياق المستخدم).
6دلالة EventID=1102

ماذا يعني حدث 1102 في سجل الأمان؟

اعرض الإجابة
يشير إلى أن سجل الأمان قد مُسح. يستحق التحقيق دائمًا، لكنه لا يثبت سوء النية تلقائيًا (قد يكون إجراءً إداريًا).
7الفرق بين 6005 و6006

ما دلالة حدثي 6005 و6006؟

اعرض الإجابة
6005 = بدء خدمة سجل الأحداث. 6006 = توقفها. الفرق بينهما يشير إلى إعادة تشغيل النظام.
8تحدي التحليل الزمني

اعرض wevtutil qe Security /c:5 /rd:true /f:text. رتّب الأحداث من الأقدم إلى الأحدث، وحدّد إن كان هناك نمط يستحق التحقيق.

اعرض التحليل
الترتيب من الأقدم: 12:30 (4624 ناجح)، 12:31 (4625 فاشل)، 12:32 (4625 فاشل)، 12:33 (4625 فاشل)، 12:35 (4624 ناجح). النمط: فشل متكرر ثم نجاح. يستحق التحقيق، وليس دليلًا قاطعًا.

الاختبار

اختبار من 10 أسئلة يغطي مفاهيم وأوامر الوحدة.

ملخص الوحدة

  • سجلات Windows تسجّل أحداث النظام والتطبيقات والأمان، وتُستخدم للتحليل الأمني.
  • السجلات الرئيسية: System, Application, Security.
  • مستويات الأحداث: Information, Warning, Error, Critical, Audit Success, Audit Failure.
  • مكونات الحدث: Event ID، Source، Level، Date/Time، User، Description.
  • wevtutil أداة سطر أوامر لقراءة سجلات Windows وإدارتها.
  • wevtutil el يعرض أسماء السجلات، wevtutil gli System يعرض معلومات سجل.
  • wevtutil qe <log> /c:5 /rd:true /f:text يعرض آخر 5 أحداث.
  • البحث عن Event ID محدد: /q:"*[System[(EventID=XXXX)]]".
  • أرقام أحداث شائعة: 4624 (تسجيل ناجح)، 4625 (تسجيل فاشل)، 1102 (مسح سجل)، 6005 (بدء سجل الأحداث).
  • حدث منفرد لا يثبت اختراقًا؛ يجب ربطه زمنيًا وبالسياق.
