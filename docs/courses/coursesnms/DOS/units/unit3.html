جمع معلومات النظام

System Information Gathering

مقدمة وأهمية الوحدة

جمع معلومات النظام هو الخطوة الأولى في أي تقييم أمني أو تحقيق. قبل أن تحكم على نظام بأنه آمن أو مخترق، يجب أن تعرف: ما إصداره؟ ما الرقع المثبتة؟ ما اسم المستخدم والجهاز والنطاق؟ ما التحديثات الناقصة؟ ما الأجهزة والبرامج المثبتة؟

في هذه الوحدة ستتعلم استخدام أوامر CMD لجمع هذه المعلومات بشكل منهجي، وتوثيقها في تقرير قابل للتحليل. التركيز هنا دفاعي: فهم حالة النظام لاكتشاف نقاط الضعف.

افتراض: تعمل على Windows 10 أو Windows 11. بعض الأوامر تختلف بين إصدارات Windows. عند الاختلاف نوضح ذلك ونذكر البديل.

أهداف الوحدة

  • تحديد هوية المستخدم والجهاز والنطاق باستخدام أوامر CMD.
  • جمع معلومات نظام التشغيل والرقع والتحديثات.
  • معرفة الأجهزة والبرامج المثبتة.
  • التعرف على المهام والخدمات الأساسية للنظام.
  • توثيق نتائج جمع المعلومات في تقرير منظم.
  • تمييز الأوامر التي تحتاج صلاحيات مسؤول.

1) هوية المستخدم — whoami

الهدف: معرفة المستخدم الحالي ونطاقه.

متى نستخدمه؟ في بداية أي فحص للتأكد من الصلاحيات.

المتطلبات: لا يحتاج صلاحيات خاصة.

الصيغة

cmd
whoami
whoami /groups
whoami /priv

شرح الخيارات:

  • بدون خيار: يعرض اسم المستخدم والنطاق.
  • /groups: يعرض مجموعات المستخدم.
  • /priv: يعرض الصلاحيات الخاصة.

خطوات التنفيذ

  1. افتح CMD.
  2. نفّذ الأمر:
cmd
whoami

المخرجات المتوقعة (نموذج):

output
desktop-7x9y2k\yousif

تفسير النتائج: الجزء قبل \ هو اسم الجهاز، وبعده اسم المستخدم.

الاستخدام الأمني: تحديد صلاحيات الجلسة قبل تنفيذ أي أمر حساس.

الأخطاء الشائعة: الاعتقاد أن الاسم الحالي يعني أنك مسؤول؛ تحقق بـ whoami /groups.

تمرين: نفّذ whoami /groups وحدد مجموعاتك.

سؤال تطبيقي: كيف تعرف إن كنت عضوًا في مجموعة Administrators؟

2) اسم الجهاز — hostname

الهدف: عرض اسم الجهاز الحالي.

متى نستخدمه؟ لتوثيق الجهاز في تقرير التحقيق.

cmd
hostname

المخرجات المتوقعة:

output
DESKTOP-7X9Y2K

تفسير النتائج: اسم الجهاز في الشبكة.

الاستخدام الأمني: توثيق الجهاز في تقرير الحادث.

الأخطاء الشائعة: الخلط بين اسم الجهاز واسم المستخدم.

تمرين: سجّل hostname وwhoami معًا.

سؤال تطبيقي: كيف يعرض whoami اسم الجهاز ضمن النتيجة؟

3) إصدار النظام — ver

الهدف: عرض إصدار Windows بسرعة.

cmd
ver

المخرجات المتوقعة (نموذج):

output
Microsoft Windows [Version 10.0.22631.3085]

تفسير النتائج: الرقم الأول 10 أو 11 هو الإصدار الرئيسي، والأرقام اللاحقة تفاصيل البناء.

الاستخدام الأمني: التحقق السريع من إصدار النظام في التقرير.

الأخطاء الشائعة: توقع تفاصيل التحديثات هنا؛ استخدم systeminfo.

تمرين: نفّذ ver وسجّل الناتج.

سؤال تطبيقي: ما الفرق بين ver وsysteminfo؟

4) معلومات النظام الشاملة — systeminfo

الهدف: عرض معلومات تفصيلية عن النظام: الإصدار، تاريخ التثبيت، ذاكرة، معالج، تحديثات مثبتة، إعدادات الشبكة.

متى نستخدمه؟ كأساس لتقرير تقييم أمني.

المتطلبات: يعمل بصلاحيات عادية، لكن بعض التفاصيل أفضل كمسؤول.

الصيغة

cmd
systeminfo
systeminfo /fo csv > systeminfo.csv

شرح الخيارات:

  • /fo csv: عرض المخرجات بصيغة CSV.
  • >: حفظ المخرجات في ملف للتحليل.

خطوات التنفيذ

  1. انتقل إلى المختبر:
cmd
cd %USERPROFILE%\Desktop\CyberPath-Lab
  1. احفظ مخرجات systeminfo في ملف:
cmd
systeminfo /fo csv > unit3_systeminfo.csv

المخرجات المتوقعة (مختصرة):

output
Host Name:                 DESKTOP-7X9Y2K
OS Name:                   Microsoft Windows 11 Pro
OS Version:                10.0.22631 N/A Build 22631
OS Manufacturer:           Microsoft Corporation
Registered Owner:          Yousif
System Boot Time:          11/06/2026, 9:15:23 AM
System Type:               x64-based PC
Hotfix(s):                 5 Hotfix(s) Installed.
                           [01]: KB5034765
                           ...

تفسير النتائج:

  • OS Version: إصدار البناء.
  • Hotfix(s): قائمة التحديثات. غياب تحديثات حديثة مؤشر خطر.
  • System Boot Time: وقت الإقلاع، مفيد لكشف إعادة تشغيل غير متوقعة.

الاستخدام الأمني: كشف نظام غير محدث أو جهاز أعيد تشغيله مؤخرًا بشكل مريب.

الأخطاء الشائعة: تنفيذ الأمر دون حفظ المخرجات، فيضيع وقت التحليل.

تمرين: احفظ مخرجات systeminfo في ملف CSV وافتحه في Excel أو Notepad.

سؤال تطبيقي: أي حقل يكشف تأخر التحديثات؟

5) معلومات إضافية عبر WMIC (متوقف تدريجيًا)

تحذير إصدارات: wmic أصبح متوقفًا تدريجيًا في Windows 11 والإصدارات الحديثة. قد لا يكون متاحًا في التحديثات الجديدة. البديل الحديث هو PowerShell. في هذه الوحدة نذكره لأنه لا يزال شائعًا في بيئات كثيرة، لكن سنستخدمه بحذر.

الهدف: الحصول على معلومات إضافية عن النظام والأجهزة.

الصيغة

cmd
wmic os get Caption,Version,BuildNumber
wmic bios get Manufacturer,Version
wmic computersystem get Manufacturer,Model

المخرجات المتوقعة (نموذج):

output
Caption          BuildNumber  Version
Microsoft Windows 11 Pro  22631   10.0.22631

تفسير النتائج: تُظهر السطر الأساسي لكل فئة.

الاستخدام الأمني: التحقق من الطراز والشركة المصنعة في تقرير تقييم الأصول.

الأخطاء الشائعة: استخدام wmic على نظام لا يدعمه، فتظهر رسالة "not recognized".

البديل: PowerShell:

powershell
Get-CimInstance Win32_OperatingSystem | Select Caption, Version, BuildNumber

تمرين: جرّب wmic؛ إن لم يعمل استخدم البديل في PowerShell.

سؤال تطبيقي: ما البديل الحديث لـ wmic؟

6) متغيرات البيئة — set

الهدف: عرض متغيرات البيئة مثل مسار المستخدم والجهاز.

cmd
set
set USERPROFILE
set COMPUTERNAME

المخرجات المتوقعة (نموذج):

output
USERPROFILE=C:\Users\Yousif
COMPUTERNAME=DESKTOP-7X9Y2K

تفسير النتائج: قيمة المتغير بعد =.

الاستخدام الأمني: كشف معلومات عن المستخدم والبيئة قد يستفيد منها المهاجم.

الأخطاء الشائعة: كتابة echo %USERPROFILE% لعرض القيمة (صحيح لكن يفضّل set USERPROFILE).

تمرين: اعرض قيم USERNAME, COMPUTERNAME, USERPROFILE.

سؤال تطبيقي: أي متغير يعرض مجلد النظام الأساسي؟ (تلميح: %SystemRoot%).

7) العمليات الجارية — tasklist

الهدف: عرض العمليات النشطة على النظام.

متى نستخدمه؟ لكشف عمليات مشبوهة أو غير متوقعة.

الصيغة

cmd
tasklist
tasklist /svc
tasklist /fo csv > unit3_tasks.csv

شرح الخيارات:

  • /svc: يعرض الخدمات المرتبطة بكل عملية.
  • /fo csv: صيغة CSV.

خطوات التنفيذ

  1. داخل المختبر، احفظ قائمة العمليات:
cmd
tasklist /fo csv > unit3_tasks.csv

المخرجات المتوقعة (نموذج):

output
Image Name, PID, Session Name, Mem Usage
System Idle Process,0,Services,8 K
System,4,Services,144 K
smss.exe,432,Services,1,232 K
...

تفسير النتائج: راجع أسماء غير مألوفة أو مسارات غريبة (يمكن معرفة المسار بـ tasklist /v أو أداة wmic).

الاستخدام الأمني: كشف عمليات التعدين أو برمجيات الفدية.

الأخطاء الشائعة: الاعتقاد أن كل عملية غير مألوفة ضارة؛ يجب التحقق من المسار والتوقيع.

تمرين: احفظ قائمة العمليات في ملف CSV، وابحث عن أسماء غير مألوفة.

سؤال تطبيقي: أي خيار يعرض الخدمات المرتبطة بكل عملية؟

8) برامج التشغيل — driverquery

الهدف: عرض برامج التشغيل المثبتة.

الصيغة

cmd
driverquery
driverquery /fo csv > unit3_drivers.csv

المخرجات المتوقعة (نموذج):

output
Module Name   Display Name           Driver Type   Link Date
1394ohci      1394 OHCI Compliant... Kernel         ...
ACPI          Microsoft ACPI Driver  Kernel         ...

تفسير النتائج: قائمة برامج التشغيل مع تواريخ الربط (Link Date). تواريخ قديمة قد تكون مؤشر مخاطر.

الاستخدام الأمني: كشف برامج تشغيل قديمة أو غير موقعة قد تُستغل لرفع الصلاحيات.

الأخطاء الشائعة: الخلط بين برامج التشغيل وبرامج التطبيقات.

تمرين: احفظ driverquery في CSV وأحصِ عدد برامج التشغيل.

سؤال تطبيقي: لماذا يهم تاريخ الربط في التقييم الأمني؟

9) البرامج المثبتة

الهدف: عرض البرامج المثبتة على النظام.

الصيغة (WMIC)

cmd
wmic product get Name,Version
wmic product get Name,Version > unit3_programs.txt

المخرجات المتوقعة (نموذج):

output
Name                                  Version
Microsoft Visual C++ 2015 Redist...   14.0.24215
...

تفسير النتائج: بعض البرامج لا تظهر في هذه القائمة لأنها مثبتة بصيغ أخرى (MSIX/Store).

الاستخدام الأمني: كشف برامج قديمة معروفة بثغرات (مثل إصدارات قديمة من Java أو Adobe).

الأخطاء الشائعة: الاعتقاد أن القائمة شاملة؛ قد تحتاج فحص سجل Windows أو PowerShell.

البديل في PowerShell:

powershell
Get-Package | Select Name, Version

تمرين: احفظ قائمة البرامج في ملف نصي.

سؤال تطبيقي: كيف تعرف إصدارات برامج معروفة بثغرات؟

10) التاريخ والوقت — date و time

الهدف: عرض أو ضبط تاريخ/وقت النظام. يهمنا العرض فقط للتوثيق.

cmd
date /t
time /t

المخرجات المتوقعة (نموذج):

output
11/07/2026
10:32 AM

تفسير النتائج: وقت النظام الحالي، لا وقت السيرفر.

الاستخدام الأمني: توثيق توقيت كل خطوة في التحقيق.

الأخطاء الشائعة: الاعتماد على وقت النظام لوحده دون مقارنته بساعة موثوقة (قد يكون مُعدّلًا من المهاجم).

تمرين: سجّل date /t وtime /t في ملف التوثيق.

سؤال تطبيقي: لماذا قد يكون وقت النظام غير موثوق؟

تطبيقات متسلسلة — جمع معلومات كامل

هذه التطبيقات تُبنى على بعضها لتكوين تقرير جمع معلومات.

التطبيق 1: تجهيز المختبر

cmd
cd %USERPROFILE%\Desktop\CyberPath-Lab

التطبيق 2: حفظ معلومات الهوية

cmd
whoami > unit3_report.txt
hostname >> unit3_report.txt
ver >> unit3_report.txt

المخرجات المتوقعة: ملف unit3_report.txt يحتوي على سطور الهوية الثلاثة.

التطبيق 3: معلومات النظام

cmd
systeminfo /fo csv >> unit3_report.txt

التطبيق 4: الوقت والتاريخ

cmd
echo === Audit Started === >> unit3_report.txt
date /t >> unit3_report.txt
time /t >> unit3_report.txt

التطبيق 5: العمليات

cmd
tasklist /fo csv >> unit3_report.txt

التطبيق 6: البرامج

cmd
wmic product get Name,Version >> unit3_report.txt

ملاحظة: قد يستغرق wmic product وقتًا طويلًا (دقيقة أو أكثر). يمكنك تخطيه إن لم يكن wmic متاحًا.

التطبيق 7: المتغيرات

cmd
set USERPROFILE >> unit3_report.txt
set COMPUTERNAME >> unit3_report.txt

التطبيق 8: برامج التشغيل

cmd
driverquery /fo csv >> unit3_report.txt

التطبيق 9: مراجعة التقرير

cmd
type unit3_report.txt

التطبيق 10: نسخة احتياطية

cmd
robocopy . .\unit3_backup /E /COPYALL

المخرجات المتوقعة: مجلد unit3_backup يحتوي نسخة من التقرير.

الأخطاء الشائعة في الوحدة

  • الاعتقاد أن systeminfo يعرض الثغرات؛ هو يعرض المعلومات فقط، تحليلها يقع عليك.
  • استخدام wmic على إصدار لا يدعمه.
  • عدم حفظ المخرجات في ملف، فتفقد الأدلة.
  • الاعتماد على وقت النظام دون مقارنة.
  • الخلط بين tasklist (العمليات) و sc query (الخدمات).

تمارين عملية

  1. نفّذ whoami /groups وحدد مجموعاتك.
  2. احفظ systeminfo في CSV وافتحه.
  3. احفظ tasklist في CSV وابحث عن أي اسم غير مألوف.
  4. اعرض driverquery واحفظ النتيجة.
  5. اجمع تقرير جمع معلومات كامل في ملف واحد.

تحديات تطبيقية

  • أنشئ سكربت .bat يجمع كل أوامر الوحدة في تقرير واحد.
  • اكتشف أكبر 3 برامج من حيث الإصدارات القديمة.
  • قارن بين ver وsysteminfo في 3 نقاط اختلاف.
  • اكتب فقرة قصيرة تفسر فيها لماذا يعتبر systeminfo أداة استطلاع دفاعية وأيضًا هجومية.

اختبار قصير

ملخص

جمعنا معلومات الهوية (whoami, hostname, ver)، معلومات النظام (systeminfo, wmic)، العمليات (tasklist)، برامج التشغيل (driverquery)، البرامج المثبتة، ومتغيرات البيئة. وبنينا تقريرًا موثقًا داخل المختبر الآمن.

مراجع موثوقة

  • Microsoft Learn — systeminfo, tasklist, driverquery, wmic.
  • Windows IT Pro Center — System Information.
  • MITRE ATT&CK — Discovery (T1082).
