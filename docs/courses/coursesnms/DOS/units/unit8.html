أساسيات أوامر Windows CMD للأمن السيبراني

الوحدة الثامنة: إعدادات الحماية وجدار الحماية في Windows

Windows Security Settings & Firewall

المقدمة

جدار الحماية (Windows Defender Firewall) هو خط الدفاع الأول الذي يتحكم في حركة اتصالات الشبكة الداخلة والخارجة من النظام.

وظيفته الأساسية: السماح بالاتصالات الضرورية فقط، ومنع كل ما هو غير مصرح به. من خلال ملفات التعريف (Profiles) والقواعد (Rules)، يمكن للمحلل الأمني ضبط سطح الهجوم وتقليل المخاطر.

في هذه الوحدة ستتعلم قراءة إعدادات جدار الحماية باستخدام netsh advfirewall، وفهم الفرق بين حالة الملف وحالة الخدمة، وتحليل القواعد التي قد تفتح ثغرات غير ضرورية — كل ذلك عبر محاكي تعليمي آمن ببيانات افتراضية.

💡
جميع المخرجات والأسماء والإعدادات في هذه الوحدة افتراضية بالكامل لأغراض التدريب. المحاكي لا يقرأ إعدادات جهازك.

أهداف التعلم

بنهاية هذه الوحدة ستكون قادرًا على:

  1. فهم دور Windows Defender Firewall في حماية النظام.
  2. التمييز بين ملفات التعريف: Domain وPrivate وPublic.
  3. فهم الفرق بين Inbound Rules وOutbound Rules.
  4. قراءة إعدادات جدار الحماية باستخدام netsh advfirewall.
  5. تفسير حالات Firewall: ON/OFF، وسلوك الاتصالات الداخلة والخارجة.
  6. التحقق من حالة خدمة Windows Defender Firewall باستخدام sc query MpsSvc.
  7. تحليل قواعد Firewall وتحديد غير الضروري منها.
  8. ربط إعدادات Firewall بتقليل سطح الهجوم ومبدأ Least Privilege.

المفاهيم الأساسية

قبل الدخول إلى الأوامر، دعنا نثبّت المفاهيم التالية:

Windows Defender Firewall
جدار حماية Windows
مكون أمني مدمج في Windows يراقب ويصفّي حركة الشبكة وفق قواعد محددة، ويُدار عبر MpsSvc.
Network Profiles
ملفات تعريف الشبكة
ثلاثة ملفات: Domain (للشبكات المنضمة لنطاق)، Private (للشبكات الموثوقة)، Public (للشبكات غير الموثوقة كالمقاهي).
Inbound Rules
قواعد الاتصالات الداخلة
تتحكم في الاتصالات القادمة إلى الجهاز من الشبكة. الافتراضي: المنع.
Outbound Rules
قواعد الاتصالات الخارجة
تتحكم في الاتصالات الصادرة من الجهاز إلى الشبكة. الافتراضي: السماح.
Allow / Block
سماح / منع
إجراء القاعدة: Allow للسماح، Block للمنع. تُطبَّق وفق الأولوية.
Firewall Profiles
ملفات تعريف الجدار
إعدادات مستقلة لكل ملف تعريف (Domain/Private/Public)، تشمل الحالة وسلوك الاتصالات.
Firewall Logging
تسجيل الجدار
تسجيل الاتصالات الممنوعة والمسموحة لملف نصي، مفيد للتحليل الجنائي.
Attack Surface Reduction
تقليل سطح الهجوم
تقليل نقاط الدخول المحتملة بإغلاق المنافذ والقواعد غير الضرورية.
Least Privilege
مبدأ أقل صلاحية
منح كل مكون الحد الأدنى فقط من الصلاحيات والاتصالات اللازمة.
Service State vs Profile State
حالة الخدمة مقابل حالة الملف
الخدمة MpsSvc قد تكون RUNNING بينما ملف Public معطّل — الفرق مهم في التحليل.
⚠️
العلاقة بين جدار الحماية وسطح الهجوم: كل قاعدة أو منفذ مفتوح يزيد سطح الهجوم. القاعدة الذهبية: أغلق ما لا تحتاجه، واسمح فقط بما تحتاجه صراحة.

شرح الأوامر

أوامر هذه الوحدة للاستعلام فقط، دون أي تعديل على إعدادات النظام.

أولًا: netsh advfirewall show allprofiles

يعرض إعدادات جدار الحماية لجميع ملفات التعريف الثلاثة في وقت واحد.

netsh advfirewall show allprofiles 
C:\> netsh advfirewall show allprofiles

Firewall Policy                        BlockInbound,AllowOutbound

RemoteManagement                       Disable

Logging:
LogAllowed                             False
LogBlocked                            True

Private Profile Settings:
----------------------------------------------------------------------
Status                                 ON
Firewall Policy                        BlockInbound,AllowOutbound

Public Profile Settings:
----------------------------------------------------------------------
Status                                 ON
Firewall Policy                        BlockInbound,AllowOutbound

التفسير الأمني: Status ON في كل الملفات = الجدار مفعّل. BlockInbound,AllowOutbound = السياسة الافتراضية (منع الداخل، السماح بالخارج). LogBlocked True = تسجيل المحاولات الممنوعة مفيد للتحليل.

سابعًا: sc query MpsSvc

يعرض حالة خدمة Windows Defender Firewall. مهم: حالة الخدمة قد تكون RUNNING بينما ملف تعريف معين معطّل — الاثنان مستقلان.

sc query MpsSvc 
C:\> sc query MpsSvc

SERVICE_NAME: MpsSvc
        TYPE               : 20  WIN32_SHARE_PROCESS
        STATE              : 4  RUNNING
                                (STOPPABLE, NOT_PAUSABLE, ACCEPTS_SHUTDOWN)
        WIN32_EXIT_CODE    : 0  (0x0)
        SERVICE_EXIT_CODE  : 0  (0x0)
        CHECKPOINT         : 0x0
        WAIT_HINT          : 0x0

التفسير الأمني: STATE 4 RUNNING = الخدمة تعمل. لكن هذا لا يعني أن كل ملفات التعريف مفعّلة. تحقق دائمًا من netsh advfirewall show allprofiles.

الحقلالمعنى
StatusON = الجدار مفعّل، OFF = معطّل
Firewall PolicyBlockInbound = منع الداخل، AllowOutbound = السماح بالخارج
LogBlockedTrue = تسجيل المحاولات الممنوعة
DirectionIn = داخل، Out = خارج
ActionAllow = سماح، Block = منع

PowerShell — تعريف نظري

Get-NetFirewallProfile هو أمر PowerShell (وليس CMD) يعرض إعدادات ملفات تعريف جدار الحماية. يستخدم عادةً عند الحاجة إلى مخرجات منظمة أو تصديرها بصيغة معينة.

ℹ️
الفرق بين CMD وPowerShell: CMD يستخدم netsh، بينما PowerShell يستخدم Get-NetFirewallProfile. النتائج متقاربة، لكن PowerShell أكثر مرونة في التصفية والتصدير. لا نطلب منك تشغيل PowerShell فعليًا في هذا التدريب.
Get-NetFirewallProfile

المحاكي التفاعلي الآمن

اكتب الأمر بنفسك أو اختر مثالًا جاهزًا. المحاكي يطابق النص مع قائمة محددة مسبقًا من المخرجات الافتراضية. لا ينفذ أوامر حقيقية، ولا يقرأ جدار حماية جهازك، ولا يتصل بأي شبكة.

🛡️
تنبيه: هذا محاكي تعليمي يعرض نتائج افتراضية ثابتة، ولا ينفذ أوامر حقيقية ولا يغيّر إعدادات جهازك.

C:\>

الأوامر المدعومة: netsh advfirewall show allprofiles · netsh advfirewall show domainprofile · netsh advfirewall show privateprofile · netsh advfirewall show publicprofile · netsh advfirewall firewall show rule name=all · netsh advfirewall show currentprofile · sc query MpsSvc

التحليل الأمني لإعدادات جدار الحماية

عند قراءة الإعدادات، ركّز على المؤشرات التالية:

  • State: OFF في أي ملف تعريف — مؤشر خطر يستحق التحقيق.
  • Firewall Policy غير متوازنة (مثل AllowInbound دائمًا) — قد تكون خطيرة.
  • قواعد Inbound تسمح بمنافذ غير ضرورية — توسّع سطح الهجوم.
  • Logging معطّل — يفقدك القدرة على التحليل الجنائي.
  • قواعد مفعّلة في ملف Public لخدمات لا تحتاج — خطر أعلى.
🚫
مؤشر واحد لا يثبت اختراقًا. يجب جمع السياق: من عدّل الإعدادات؟ متى؟ هل كان هناك نشاط مشبوه قبله؟ لا تعتمد على حقل واحد.

سيناريوهات افتراضية

1ملف Public معطّل

عند تنفيذ netsh advfirewall show publicprofile، تجد Status OFF.

سؤال: ما التحليل؟

اعرض التحليل المتوقع
مؤشر خطر مرتفع. ملف Public يُستخدم في الشبكات غير الموثوقة (مقاهي، مطارات). تعطيله يعني أن الجهاز مكشوف للاتصالات الخارجية. هذا يستحق التحقيق: من عطّله؟ هل كان إجراءً مقصودًا أم خطأً؟ ما الأحداث الأخرى في نفس النافذة الزمنية؟
2قاعدة Inbound غير ضرورية

قاعدة Firewall تسمح بـ TCP على المنفذ 8080 في ملف Public، بينما لا يوجد تطبيق يحتاجها.

سؤال: ما المخاطر؟

اعرض التحليل المتوقع
فتح منفذ غير مستخدم في ملف Public يزيد سطح الهجوم. قد يستغله برنامج خبيث لاحقًا، أو يكون منفذًا لخدمة نُسيت. الإجراء الصحيح: تعطيل القاعدة بعد التأكد من عدم الحاجة (في بيئة إنتاج، وليس هنا).
3مقارنة الملفات الثلاثة

Domain وPrivate حالتهم ON، لكن Public OFF.

سؤال: ما تفسير ذلك؟

اعرض التحليل المتوقع
قد يكون تعطيلًا مقصودًا من مسؤول للسماح باتصالات أثناء اختبار داخلي، أو خطأً نتج عن تطبيق سياسة خاطئة، أو تعديلًا من مهاجم. لا يمكن الحكم من البيانات وحدها؛ يجب مراجعة سجلات التغيير والأحداث المرتبطة.
4حالة خدمة MpsSvc

sc query MpsSvc يعرض STATE 4 RUNNING، لكن Public Profile OFF.

سؤال: هل هذا تناقض؟

اعرض التحليل المتوقع
لا. حالة الخدمة وحالة ملف التعريف مستقلتان. الخدمة قد تعمل (RUNNING) بينما أحد الملفات معطّل. تحقق دائمًا من كليهما: sc query MpsSvc وnetsh advfirewall show allprofiles.

التمارين والتحديات

استخدم المحاكي أعلاه. جميع النتائج افتراضية.

1عرض جميع ملفات التعريف

ما الأمر الذي يعرض إعدادات ملفات التعريف الثلاثة معًا؟

اعرض الإجابة
netsh advfirewall show allprofiles
2حالة ملف Public

كيف تعرض حالة ملف Public فقط؟

اعرض الإجابة
netsh advfirewall show publicprofile
3حالة خدمة الجدار

ما الأمر للتحقق من حالة خدمة Windows Defender Firewall؟

اعرض الإجابة
sc query MpsSvc
4قواعد Firewall

كيف تعرض جميع قواعد Firewall (Inbound/Outbound)؟

اعرض الإجابة
netsh advfirewall firewall show rule name=all
5التمييز بين Inbound وOutbound

من مخرجات show rule name=all، كيف تعرف أن قاعدة ما هي Inbound؟

اعرض الإجابة
من حقل Direction: In = داخلة، Out = خارجة.
6تحليل سياسة غير آمنة

إذا وجدت Firewall Policy AllowInbound,AllowOutbound، ما المخاطر؟

اعرض التحليل
السماح بكل الاتصالات الداخلة يفتح سطح الهجوم بالكامل. السياسة الطبيعية BlockInbound,AllowOutbound.
7قاعدة Allow على منفذ غير مستخدم

قاعدة Allow TCP 8080 In Public لبرنامج غير موجود. ما التقييم؟

اعرض التحليل
قاعدة غير ضرورية توسّع سطح الهجوم. يُنصح بتعطيلها في بيئة إنتاج. لا تعطّلها هنا.
8الفرق بين CMD وPowerShell

ما الفرق بين netsh advfirewall show allprofiles وGet-NetFirewallProfile؟

اعرض الإجابة
الأول في CMD، والثاني في PowerShell. كلاهما يعرض إعدادات ملفات التعريف، لكن PowerShell يوفر مخرجات منظمة أكثر ومرونة في التصفية.

الاختبار

اختبار من 10 أسئلة يغطي مفاهيم وأوامر الوحدة.

ملخص الوحدة

  • Windows Defender Firewall يتحكم في حركة الشبكة الداخلة والخارجة.
  • ثلاثة ملفات تعريف: Domain, Private, Public — كل منها بإعدادات مستقلة.
  • Inbound Rules الافتراضي منع، Outbound Rules الافتراضي سماح.
  • netsh advfirewall show allprofiles يعرض إعدادات الملفات الثلاثة.
  • netsh advfirewall show publicprofile يعرض ملف Public فقط.
  • netsh advfirewall firewall show rule name=all يعرض كل القواعد.
  • sc query MpsSvc يعرض حالة خدمة الجدار — مستقلة عن حالة الملفات.
  • Get-NetFirewallProfile أمر PowerShell مكافئ، وليس CMD.
  • تعطيل Public Profile أو قاعدة غير ضرورية = توسيع سطح الهجوم.
  • مبدأ Least Privilege: اسمح فقط بما تحتاجه صراحة، وأغلق الباقي.
