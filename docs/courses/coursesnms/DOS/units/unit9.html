الوحدة التاسعة: المهام المجدولة وتحليل الاستمرارية في Windows

Windows Scheduled Tasks & Persistence Analysis

المقدمة

المهام المجدولة (Scheduled Tasks) إحدى الركائز التي تعتمد عليها أنظمة Windows لتشغيل مهام دورية في أوقات محددة أو عند أحداث معينة. لكنها أيضًا إحدى آليات الاستمرارية (Persistence) التي يستغلها المهاجمون لضمان بقاء نشاطهم على النظام بعد إعادة التشغيل.

في هذه الوحدة ستتعلم قراءة المهام المجدولة باستخدام schtasks، وتحليل بياناتها الدفاعية: الاسم، المسار، المشغّل، الإجراء، والحساب المستخدم. كل ذلك داخل محاكي تعليمي آمن ببيانات افتراضية.

💡
جميع المخرجات والأسماء والمسارات والتواريخ في هذه الوحدة افتراضية بالكامل لأغراض التدريب. المحاكي لا يقرأ مهام جهازك.

أهداف التعلم

بنهاية هذه الوحدة ستكون قادرًا على:

  1. فهم دور Windows Task Scheduler في إدارة المهام المجدولة.
  2. التمييز بين المهمة المجدولة وآلية الاستمرارية.
  3. قراءة معلومات المهام المجدولة باستخدام schtasks /query.
  4. تفسير الحقول: Task Name، Task Path، Trigger، Action، Run As.
  5. التمييز بين مهام نظامية مشروعة ومهام تستحق التحقيق.
  6. تحليل بيانات افتراضية واستخلاص مؤشرات للمراجعة الأمنية دون جزم مسبق.

المفاهيم الأساسية

قبل الدخول إلى الأوامر، دعنا نثبّت المفاهيم التالية:

Task Scheduler
مجدول المهام
خدمة نظام في Windows مسؤولة عن تشغيل المهام وفق شروط محددة (وقت، حدث، تسجيل دخول).
Scheduled Task
مهمة مجدولة
مهمة لها اسم ومسار ومشغّل وإجراء وحساب تشغيل. تُخزَّن في مجلدات ضمن \Microsoft\Windows\ أو مجلدات مخصصة.
Task Trigger
مشغّل المهمة
الشرط الذي يؤدي إلى تشغيل المهمة: وقت مجدول، تسجيل دخول، بدء تشغيل النظام، حدث، خمول.
Task Action
إجراء المهمة
ما تفعله المهمة عند تشغيلها: تشغيل برنامج، إرسال بريد، عرض رسالة. أهم حقل للمحلل الأمني هو مسار الملف التنفيذي.
Run As / Security Context
حساب التشغيل
الحساب الذي تعمل به المهمة: SYSTEM أو حساب مستخدم أو حساب خدمة. الحساب المرتفع الصلاحيات يستحق التحقق.
Task History
سجل المهمة
سجل تنفيذ المهمة ونتائجها. قد يكون معطّلًا أو غير متاح إذا لم يُفعّل تسجيل الأحداث — لذا غياب الأحداث لا يعني بالضرورة أن المهمة لم تعمل.
Persistence Mechanism
آلية استمرارية
أي وسيلة تضمن بقاء نشاط (شرعي أو خبيث) على النظام بعد إعادة التشغيل. المهام المجدولة إحداها.
Least Privilege
مبدأ أقل صلاحية
يجب أن تعمل المهمة بأقل صلاحيات كافية لأداء غرضها. حساب SYSTEM لمهمة لا تحتاجه مؤشر يستحق التحقق.
⚠️
مهم: اسم المهمة وحده لا يكفي للحكم عليها. قد يحمل برنامج خبيث اسم مهمة نظامية ليبدو شرعيًا. الحكم يحتاج: المسار، الإجراء، الحساب، التوقيت، والتوقيع الرقمي.
ℹ️
الفرق بين مهمة مشروعة ومشبوهة: المهمة المشروعة عادةً في مسار نظامي معروف، باسم واضح، تعمل بحساب مناسب، وتنفذ ملفًا موقّعًا من ناشر معروف. المهمة المشبوهة تُظهر شذوذًا في أحد هذه الجوانب أو أكثر — لكن الشذوذ وحده ليس دليلًا قاطعًا.

شرح الأوامر

جميع الأوامر التالية للاستعلام فقط، دون تعديل أو إنشاء أو حذف أي مهمة.

أولًا: schtasks /query

يعرض قائمة المهام المجدولة في النظام. يُستخدم كبداية للاستكشاف.

سادسًا: schtasks /?

يعرض المساعدة الكاملة للأمر، بما فيها جميع المعاملات المدعومة.

schtasks /? 
C:\> schtasks /?

Description:
    Enables an administrator to create, delete, query, change, run and

Parameter List:
    /Create          Creates a new scheduled task.
    /Delete          Deletes the scheduled task(s).
    /Query           Displays all scheduled tasks.
    /Change          Changes the properties of scheduled task.

Examples:

ℹ️
ملاحظة: هذه الوحدة تستخدم /Query فقط. لا نستخدم /Create أو /Delete أو /Change أو /Run أو /End — التحليل الدفاعي فقط.

Task Scheduler GUI — تعريف نظري

واجهة Task Scheduler الرسومية تتيح تصفح المهام في شجرة على اليمين، وعرض تفاصيلها في الأسفل (General، Triggers، Actions، Conditions، History). تعرض نفس المعلومات التي يوفرها schtasks لكن بصيغة رسومية أوضح.

في التحليل الأمني، ركّز على: اسم المهمة، مسار المهمة، المشغّل (Trigger)، الإجراء (Action)، والحساب المستخدم.

⚠️
قبل اعتبار مهمة مشبوهة، تحقق من: مسار الملف التنفيذي، توقيعه الرقمي، مالكه، وتاريخ إنشائه. الاسم وحده لا يكفي.

المحاكي التفاعلي الآمن

اكتب الأمر بنفسك أو اختر مثالًا جاهزًا. المحاكي يطابق النص مع قائمة محددة مسبقًا من المخرجات الافتراضية. لا ينفذ أوامر حقيقية، ولا يقرأ مهام جهازك، ولا يتصل بأي شبكة.

🛡️
تنبيه: هذا محاكي تعليمي يعرض نتائج افتراضية ثابتة، ولا ينفذ أوامر حقيقية ولا يقرأ مهام جهازك.
محاكي schtasks التعليمي — نتائج افتراضية ثابتة
📅
التواريخ الظاهرة في المخرجات (مثل 2025) جزء من سيناريو تعليمي افتراضي ولا تعكس جهازك أو تاريخك الفعلي.
C:\>
// المحاكي جاهز. اكتب أمرًا في الحقل أعلاه أو اختر مثالًا جاهزًا.
الأوامر المدعومة: schtasks /query · schtasks /query /fo LIST · schtasks /query /fo TABLE · schtasks /query /v /fo LIST · schtasks /query /tn "..." · schtasks /?
ملاحظة: أوامر التغيير مثل /Create، /Delete، /Change، /Run، /End غير مدعومة (نظرية فقط).

التحليل الأمني للمهام المجدولة

المؤشرات التالية تستحق التحقق، وليست دليلًا قاطعًا على وجود اختراق:

  • اسم مهمة غير مألوف أو يحاول تقليد اسم مهمة نظامية.
  • تشغيل ملف تنفيذي من مجلد مؤقت أو مسار مستخدم غير معتاد.
  • استخدام حساب مرتفع الصلاحيات (SYSTEM) دون مبرر واضح.
  • مشغّل (Trigger) متكرر أو غير متوقع مثل كل دقيقة.
  • اختلاف مسار الملف أو خصائص المهمة عن خط الأساس المعتمد.
  • مهمة في مجلد مخصص تحت اسم يشبه اسمًا نظاميًا.
🚫
مؤشر واحد لا يثبت اختراقًا. الحكم يتطلب: التحقق من التوقيع الرقمي للملف، مالكه، تاريخ إنشائه، سجلات النظام، والأحداث المحيطة.

السيناريوهات الثلاثة

البيانات التالية افتراضية بالكامل، وتواريخها (2025) جزء من السيناريو التعليمي ولا تعكس جهازك.

1مهمة نظامية معروفة

بيانات المهمة:

TaskName: \Microsoft\Windows\Defrag\ScheduledDefrag
Task To Run: %windir%\system32\defrag.exe
Run As User: SYSTEM
Schedule Type: Weekly

سؤال: هل هذه المهمة مشبوهة؟

اعرض التحليل المتوقع
لا يوجد في البيانات ما يستدعي الشك. اسم المهمة ومسارها يتوافقان مع مهمة نظام Windows المعتادة، والإجراء يُشغّل defrag.exe من مسار النظام.

لكن التوقيع الرقمي للملف يجب التحقق منه بصورة مستقلة — المسار والاسم وحدهما لا يكفيان للجزم بأن الملف أصلي ولم يُستبدل. تحقق أيضًا من: المالك، تاريخ الإنشاء، وسجلات النظام المرتبطة.
2مهمة باسم غير مألوف ومسار مؤقت

بيانات المهمة:

TaskName: \CustomTasks\WindowsUpdateHelper
Task To Run: C:\Users\Public\wuhelper.exe /silent
Run As User: SYSTEM
Schedule Type: Daily

سؤال: ما المؤشرات التي تستحق التحقيق؟

اعرض التحليل المتوقع
المؤشرات التي تستحق التحقيق:
  • اسم يشبه مهمة نظامية (WindowsUpdateHelper) لكنه في مجلد مخصص (\CustomTasks) وليس في مسار Microsoft.
  • المسار التنفيذي في مجلد المستخدم العام (C:\Users\Public\) — وهو غير معتاد لملفات النظام.
  • حساب SYSTEM مرتفع الصلاحيات رغم أن الملف في مسار مستخدم.

لكن هذه مؤشرات وليست أدلة. يجب التحقق من: التوقيع الرقمي، المالك، تاريخ الإنشاء، وسجلات النظام — قبل الحكم.
3مهمة بحساب SYSTEM وغرض غير واضح

بيانات المهمة:

TaskName: \Maintenance\LogRotator
Task To Run: C:\Program Files\LogTools\rotate.exe
Run As User: SYSTEM
Schedule Type: Every 5 minutes

سؤال: ما تقييمك؟

اعرض التحليل المتوقع
مؤشرات تستحق التحقق: المسار في Program Files معتاد للبرامج المشروعة، لكن الجدولة كل 5 دقائق غير معتادة لأداة تدوير سجلات، وحساب SYSTEM أوسع مما تحتاجه عادةً.

لا يُحكم بأن المهمة خبيثة أو مشروعة من هذه البيانات وحدها. تحقق من: الغرض الموثّق، التوقيع الرقمي، من أنشأ المهمة، والتكرار الفعلي في السجلات.

التمارين والتحديات

استخدم المحاكي أعلاه. جميع النتائج افتراضية.

1عرض كل المهام

ما الأمر الذي يعرض قائمة بجميع المهام المجدولة؟

اعرض الإجابة
schtasks /query
2صيغة LIST

ما الأمر الذي يعرض المهام بصيغة قائمة مفصّلة؟

اعرض الإجابة
schtasks /query /fo LIST
3تفاصيل موسّعة

ما الأمر الذي يعرض تفاصيل موسّعة لكل مهمة؟

اعرض الإجابة
schtasks /query /v /fo LIST
4الاستعلام عن مهمة محددة

كيف تعرض تفاصيل مهمة ScheduledDefrag بمسارها الكامل؟

اعرض الإجابة
schtasks /query /tn "\Microsoft\Windows\Defrag\ScheduledDefrag"
5الحقل الأهم للتحليل

من مخرجات /v /fo LIST، أي حقل يوضح الملف التنفيذي الذي تشغله المهمة؟

اعرض الإجابة
Task To Run
6تقييم حساب التشغيل

مهمة تعمل بحساب SYSTEM لكن الإجراء يقرأ فقط ملفًا في مجلد المستخدم. ما التقييم؟

اعرض التحليل
قد يكون الحساب أوسع من الحاجة، ما يخالف مبدأ أقل صلاحية. لكنه لا يُثبت الخبث — قد يكون الحساب مطلوبًا لسبب تقني (مثل الوصول لمورد نظامي). تحقق من الغرض الموثق للمهمة.
7مؤشر vs دليل

مهمة بمسار غير معتاد: هل هي دليل على اختراق؟

اعرض الإجابة
لا. مسار غير معتاد مؤشر يستحق التحقق، وليس دليلًا. يجب فحص التوقيع الرقمي، المالك، تاريخ الإنشاء، وسجلات النظام.
8خطوات التحقق الدفاعية

ما الخطوات الصحيحة للتحقق من مهمة مشبوهة؟

اعرض الإجابة
1) مراجعة المسار الكامل للملف التنفيذي، 2) التحقق من التوقيع الرقمي، 3) معرفة المالك ومن أنشأ المهمة، 4) مراجعة سجلات المهمة وتاريخ الإنشاء، 5) مقارنة بخط الأساس المعروف. لا تُحذف المهمة قبل جمع السياق.

الاختبار

اختبار من 10 أسئلة يغطي مفاهيم وأوامر الوحدة.

ملخص الوحدة

  • Task Scheduler خدمة Windows مسؤولة عن تشغيل المهام المجدولة.
  • المهمة المجدولة لها اسم ومسار ومشغّل وإجراء وحساب تشغيل.
  • المهام المجدولة إحدى آليات الاستمرارية التي يستغلها المهاجمون.
  • schtasks /query يعرض المهام، و/fo LIST يعرضها مفصّلة.
  • /v /fo LIST يعرض تفاصيل موسّعة تشمل Task To Run وRun As User.
  • /tn يستعلم عن مهمة محددة بمسارها الكامل.
  • اسم المهمة وحده لا يكفي للحكم عليها؛ تحقق من المسار والتوقيع والحساب.
  • الجدولة المتكررة جدًا أو حساب SYSTEM غير المبرَّر مؤشرات تستحق التحقيق.
  • مؤشر واحد لا يثبت اختراقًا؛ يجب جمع السياق قبل الحكم.
  • مبدأ أقل صلاحية: اسمح للمهمة بأقل صلاحيات كافية لغرضها.

☑️ قائمة تحقق سريعة عند مراجعة المهام المجدولة

  • هل اسم المهمة ومسارها معتادان في بيئتك؟
  • هل Task To Run يشير إلى مسار نظامي أو مسار مستخدم غير معتاد؟
  • هل الملف التنفيذي موقّع رقميًا من ناشر معروف؟
  • هل Run As User مناسب لغرض المهمة (وليس أوسع من الحاجة)؟
  • هل Schedule Type معقول (ليس كل دقيقة مثلًا)؟
  • من هو Author ومتى أُنشئت المهمة؟
  • هل توجد مهام أخرى مشابهة في نفس المجلد المخصص؟
  • هل سجلات النظام تُظهر أحداثًا مشبوهة قريبة من وقت الإنشاء؟
