35 — مقدمة لثغرات تطبيقات الويب

مقدمة مختصرة: ثغرات تطبيقات الويب هي نقاط ضعف في مواقع الويب أو واجهات برمجة التطبيقات (APIs) تسمح للمهاجم باستغلالها للوصول غير المصرح به أو التلاعب بالبيانات أو تنفيذ أوامر ضارة. مصدر شائع للثغرات هو مدخلات المستخدم غير المفلترة أو التهيئات الافتراضية الضعيفة.

ملاحظة للمدرب: اذكر أمثلة بسيطة يمكن للمتدربين رؤيتها (نماذج صفحات تسجيل دخول بدون تصفية، حقول بحث تقبل نصوص SQL، أو رسائل خطأ تكشف تفاصيل النظام).
مراجع فيديو مقترحة:
  • مقدمة OWASP وTop 10 (فيديو)
  • لمحة عن ثغرات تطبيقات الويب

36 — SQL Injection (مفهوم، تأثير، وقاية)

المفهوم:

SQL Injection هي ثغرة تسمح للمهاجم بإدخال جزء من استعلام SQL عبر مدخلات غير سليمة ليقوم النظام بتنفيذ أوامر غير مقصودة على قاعدة البيانات.

التأثير:
  • كشف أو سرقة بيانات حساسة (مثل بيانات المستخدمين وكلمات المرور).
  • تعديل أو حذف سجلات.
  • الحصول على تحكم في الخادم في بعض الحالات.
طرق الوقاية (مقترحة):
  • استخدام استعلامات مُعدة (Prepared Statements) أو ORM
  • التحقق من صحة المدخلات (Input Validation)
  • تقييد صلاحيات حساب قاعدة البيانات (Least Privilege)
  • استخدام جدران تطبيق الويب (WAF) كطبقة حماية إضافية
مثال توضيحي (مفاهيمي): 
غير آمن: SELECT * FROM users WHERE username = ' " + user + " ' AND password = ' " + pass + " ';
آمن: PreparedStatement ps = conn.prepareStatement("SELECT * FROM users WHERE username = ? AND password = ?");
انتقل إلى: كيفية توثيق ثغرة

37 — XSS (الأنواع، أمثلة، الوقاية)

الأنواع:
  • Stored XSS — يتم تخزين الشيفرة الخبيثة في الخادم وتُعرض للزوار لاحقًا.
  • Reflected XSS — يُرجع الخادم محتوى يحتوي شيفرة خبيثة استنادًا إلى إدخال المستخدم.
  • DOM-based XSS — تنفّذ الشيفرة على جانب العميل بسبب معالجة غير آمنة للـ DOM.
الوقاية:
  • تصفية وفرملة المدخلات (Input Sanitization / Output Encoding)
  • استخدام سياسات أمان المحتوى (CSP)
  • تجنب إدراج مدخلات المستخدم في HTML دون تنظيف
قراءة OWASP عن XSS

38 — CSRF (المبدأ والوقاية)

المبدأ: CSRF (Cross-Site Request Forgery) يحدث عندما يُخدع متصفح مستخدم موثوق لتنفيذ إجراء غير مقصود لدى خادم موثوق به، عادة باستخدام جلسة فعّالة (logged-in session).

طرق الوقاية:
  • استخدام رموز CSRF (tokens) المولّدة عشوائيًا لكل جلسة/نموذج
  • استخدام التعريف SameSite لملفات تعريف الارتباط (cookies)
  • التحقق من عناوين المرجعية (Referrer) أو Origin في الطلبات الحساسة
تلميح عملي: في تطبيقات RESTful تأكد أن عمليات التغيير تستخدم طرق HTTP الصحيحة (POST/PUT/DELETE) مع تحقق CSRF حيثما يلزم.

39 — مسار الكشف والتوثيق: كيف تكتب تقرير ثغرة

عناصر تقرير الثغرة النموذجي:

  1. ملخص تنفيذي (Executive Summary) — وصف قصير لمديري المؤسسة.
  2. تفاصيل الثغرة — وصف تقني مع خطوات إعادة الإنتاج (reproducible steps).
  3. أدلة داعمة — لقطات شاشة، لقطات طلب HTTP/Response، سجلات.
  4. خطورة التهديد (CVSS أو تصنيف داخلي).
  5. التأثير المحتمل والأمثلة العملية.
  6. توصيات الإصلاح (وخطوات مقترحة).
  7. مراجع وملاحظات إضافية.
نموذج خطوات إعادة الإنتاج (مثال): وصف كل خطوة برقم تسلسلي (1) فتح الصفحة — (2) إدخال القيمة — (3) ملاحظة الاستجابة — وإرفاق لقطة شاشة.
اذهب إلى النشاط العملي (Juice Shop)

40 — نشاط عملي: دليل مختصر لمهمة في OWASP Juice Shop

ملاحظة مهمة:

كل الأنشطة يجب أن تُنفّذ داخل بيئة مختبرية معزولة (لا تُنفذ أي اختبارات على أنظمة أو مواقع حقيقية دون إذن).

مهمة مقترحة — اكتشاف ثغرة تسجيل دخول ضعيفة (مستوى مبتدئ):
  1. قم بتشغيل OWASP Juice Shop في بيئتك (docker أو VM).
  2. افتح صفحة تسجيل الدخول/الاستعلام.
  3. جرب إدخالات بحث بسيطة للتعرف على سلوك التطبيق (مثلاً: حقول إدخال تعرض رسائل خطأ مفصلة).
  4. دوّن أي رسائل خطأ أو سلوك غير متوقع، ثم دون خطوات قابلة لإعادة الإنتاج.
  5. اكتب تقرير مصغر يحوي وصف الثغرة، خطوات إعادة الإنتاج، وأقل تقدير للتأثير والتوصيات.
مثال: 1) افتح /search  2) أدخل  3) راقب إذا ظهرت نافذة أو سلوك غير متوقع (ملاحظة: هذا مثال توضيحي — لا تستغل فعليًا على أنظمة خارج المختبر)

41 — تعريف التشفير وأهميته

التشفير هو عملية تحويل البيانات إلى شكل غير مقروء (ciphertext) بحيث لا يمكن فهمها بدون مفتاح فك التشفير. يوفر التشفير السرية أثناء التخزين والانتقال، ويقلّل من خطورة التسريبات.

مثال عملي: HTTPS (TLS) يضمن تشفير النقل بين متصفح المستخدم والموقع، بينما تشفير قواعد البيانات يحمي البيانات في حالة تسريب الملفات.

42 — التشفير المتماثل vs غير المتماثل

التشفير المتماثل (Symmetric)

يستخدم نفس المفتاح للتشفير وفك التشفير. مثال: AES. سريع ومناسب لتخزين أو تبادل بيانات داخل نظام مغلق.

التشفير غير المتماثل (Asymmetric)

يستخدم زوج مفاتيح: مفتاح عام للتشفير ومفتاح خاص لفك التشفير. مثال: RSA, ECC. مفيد لتبادل المفاتيح وآليات التوقيع الرقمي.

ملاحظة المدرب: اشرح كيف يجتمعان عمليًا: غالبًا تُستخدم تشفيرًا متماثلًا في القنوات بعد أن يتم تبادل المفتاح بأمان بواسطة تشفير غير متماثل (مثال: TLS).

43 — إدارة المفاتيح والتوقيعات الرقمية (مفاهيمي)

إدارة المفاتيح (Key Management) تتضمن توليد المفاتيح، تخزينها بشكل آمن، تدويرها (rotation)، وسحبها (revocation). التوقيعات الرقمية تضمن صحة المصدر وعدم التلاعب بالمحتوى.

  • استخدم Hardware Security Module (HSM) عند الحاجة لحماية المفاتيح عالية الحساسية.
  • تدوير المفاتيح بشكل دوري يقلل من أثر التسريب.
  • سجل العمليات الخاصة بالمفاتيح لمراجعة أي استخدام غير مصرح.

44 — تعتيم البيانات وأنماط التخزين الآمن

تعتيم البيانات (Data Masking): استبدال أجزاء من البيانات الحساسة بمعلومات غير حقيقية (مثال: إظهار آخر 4 أرقام من رقم البطاقة فقط).

أنماط التخزين الآمن:

  • التشفير في الراحة (Encryption at rest) — تشفير قواعد البيانات والنسخ الاحتياطية.
  • التشفير أثناء النقل (TLS) — للحماية أثناء تبادل البيانات.
  • تقليل الاحتفاظ بالبيانات (Data minimization).

45 — نشاط/ورقة عمل: اختيار خوارزمية مناسبة لحالة استخدام

تعليمات النشاط: قسّم المتدربين إلى مجموعات. أعطِ كل مجموعة حالة استخدام (مثلاً: تشفير بيانات دفاتر الرواتب، تشفير قنوات الدفع، توقيع ملفات برنامج). على كل مجموعة اقتراح خوارزمية ملائمة (AES, RSA, ECC, SHA-256) مع مبررات قصيرة.

مدة النشاط: 30 دقيقة — ثم 15 دقيقة عرض ومناقشة.

معايير التقييم: ملاءمة الخوارزمية للحالة، مراعاة الأداء والتخزين وإدارة المفاتيح، وجود خطة لتدوير/استبدال المفاتيح.
